# 项目需求分析

## 目标与范围

校园食堂菜品浏览、预约点餐、取餐、评价及基础后台管理课程设计。个人开发者 2～3 周完成。采用前后端分离和模块化单体，不做真实支付、退款、配送、优惠券、微服务或复杂推荐。

## 用户

- 学生：注册登录、浏览分类/菜品、搜索、购物车、预约下单、查询订单、符合条件时取消、确认取餐、评价已完成订单菜品、查看热门排行。
- 管理员：维护分类、菜品、价格、库存和上下架；处理订单；管理用户、审核评论；查看销量统计。

## 功能需求

1. 注册账号（学号唯一），角色由服务端固定为学生；密码哈希存储。管理员账号通过本地初始化建立，不开放注册提权。
2. 公开浏览启用分类及在售菜品，查看价格、图片 URL、介绍、库存；按名称搜索，列表分页。
3. 用户购物车同一菜品一行，可新增、改数量、删除。展示价仅供参考，下单重新读取价格和库存。
4. 下单选择预约日期和时段；默认仅未来 7 天，固定午餐/晚餐时段，不做容量排班。后端计算总额、保存价格/名称快照、事务扣库存。下单幂等键防止网络重试重复创建。
5. 状态：`PENDING`待管理员确认、`PREPARING`备餐中、`READY`可取餐、`COMPLETED`已取餐、`CANCELLED`已取消。学生只可取消 `PENDING`；管理员可按规则取消未完成订单。学生在 `READY` 确认取餐，管理员可代确认。
6. 订单包含一至多件菜品。仅完成订单可评价，每订单明细最多一条；1～5 星，完成后 30 天内提交/编辑，默认待审核。仅审核通过评论公开并计入评分。
7. 管理员可启停用户但不能查看明文密码；分类/菜品/用户历史关联不物理删除。统计订单数、完成单数、完成订单销售额和销量排行。

## 假设和规则

- 角色仅 `STUDENT`、`ADMIN`；登录账号为学号/管理员账号。
- 取餐时段存 `LUNCH`/`DINNER`；示例时段午餐 11:00–13:30、晚餐 17:00–19:30。本期不做具体分钟预约和容量管理。
- 库存为可售份数，下单成功即扣，合法取消时恢复一次。价格使用人民币元，后端以 `BigDecimal` 运算。
- 图片只保存 URL，不包含上传服务。删除采用下架/停用。
- 热门菜品按已完成订单销售数量排序，并列按 ID 稳定排序。

## 非功能与验收

- 常见列表分页；接口输入校验；统一异常响应；密码/JWT/角色保护；本机容易启动演示。
- 学生不能访问管理员能力或他人订单；前端金额不影响订单金额；库存不能扣成负数；历史价格不受改价影响；不符合状态的取消/评价拒绝；待审评论不公开。
