# 用户角色和权限设计

## 身份与认证

角色仅 `STUDENT`、`ADMIN`。密码用 BCrypt 哈希，登录成功后签发 JWT（subject 用户 ID、角色、iat、exp），JWT 密钥从 `JWT_SECRET` 读取。访问令牌有效期 2 小时；初期不做刷新/黑名单，退出由前端清除。注册固定学生角色；管理员通过本地初始化建立，不能公开注册提权。禁用账号拒绝后续登录认证。由于当前使用无状态 JWT，已经签发的令牌在过期前仍可能有效；当前不支持即时撤销。

## 权限矩阵

| 能力 | 访客 | 学生 | 管理员 |
|---|---|---|---|
| 注册/登录 | 是 | 是 | 是 |
| 浏览分类、在售菜品、已审核评价、排行 | 是 | 是 | 是 |
| 资料、购物车、下单、订单查询 | 否 | 本人 | 否 |
| 取消/确认取餐 | 否 | 本人且状态符合 | 可处理订单 |
| 评价 | 否 | 本人已完成订单明细 | 否 |
| 分类/菜品维护 | 否 | 否 | 是 |
| 全量订单处理、用户启停、评论审核、统计 | 否 | 否 | 是 |

## 执行规则

后端 JWT 过滤器校验签名和有效期，安全上下文建立后由 Spring Security 按路径授权；Service 再检查资源归属和业务资格。学生身份从认证上下文获取，不信任请求 userId。学生不能访问他人订单/购物车/评价；不属于本人资源可返回 404。未认证 401，角色不足 403。公开评论只返回 APPROVED。

评价必须关联同一用户的已完成订单、订单明细和菜品，且未超 30 天；审核状态只有管理员修改。用户管理不得查看密码或修改角色。JWT 密钥与密码不入 Git/日志；本地 HTTP 仅开发，部署使用 HTTPS。
